# Card patterns (CARD-ANALYSIS agent)

Source: `data/cards.json` (1103 canonical cards, 1087 with rules text). Generated by `npx tsx tools/analyze-cards.ts`, which writes
`data/card-analysis.json` (per card: parsed abilities and pattern ids), `data/card-patterns.json` (the catalogue below as JSON),
`data/card-batches.json` and the GENERATED blocks in this file and in `docs/card-batches.md`. Re-run it after `tools/build-cards.ts`.
Everything outside the GENERATED blocks is written by hand.

Data quirks the scripting agents must know about (the analyser handles all of them):

- **Unbracketed keywords**: ogn-005-298 `Action`, sfd-096-221 `Ganking`, sfd-138-221 `Hidden`, ven-073-166 `Equip [C]`, rad-071-167 `Equip [1]`.
- ven-109-166 Illaoi: in "play a `[1]` `[S]` Tentacle unit token" the `[1]` is the token's **Might**, not Energy.
- rad-048-167 uses an en dash: `–[S]` = `-[S]`. rad-127-167's text ends with the stray junk `disa`.
- **`CardDef.keywords` cannot be trusted as "keywords this card has".** `tools/build-cards.ts` collects every bracketed keyword in the reminder text, including keywords the card grants, references or only mentions in a token reminder. 189 cards get keywords they don't have (for example rad-001-167 Amateur Demolitionist gets `Deploy` from the Bomb token reminder, and rad-037-167 gets `Deflect` because it grants it). 5 cards with unbracketed keywords are missing theirs. Use `card-analysis.json[id].intrinsicKeywords` (e.g. `["Assault 2","Shield 2"]`) and `keywordCosts` (e.g. `{"Equip":"[C], Recycle 2 cards from your trash"}`) instead.
- Some **parentheticals carry rules**, and `text` drops them because `build-cards` strips every `(...)` as reminder text. Examples: "(You still pay its costs.)", "(Use only if unattached.)", "(Tokens aren't cards.)", "(even if I'm no longer on the board)". The full list is in section 7. Scripts should implement the `reminderText` version of these.

## 2. How abilities are classified (`data/card-analysis.json`)

```ts
analysis[cardId] = {
  name, type, set, text,
  scriptNeed: 'script' | 'keywords-only' | 'reminder-only' | 'none',
  intrinsicKeywords: string[],          // e.g. ["Accelerate","Assault 2"]
  keywordCosts: Record<string,string>,  // Equip/Empower/Repeat/Flow cost strings
  abilities: Array<{
    index, raw,                         // normalised source line(s) ([T]->[E], [S]->[M], " — "->[>])
    kind: 'keyword' | 'keyword-cost' | 'triggered' | 'activated' | 'static' | 'replacement'
        | 'spell-effect' | 'play-modifier' | 'reminder',
    keywords?, prefixes?: {keyword, role:'dependent'|'trigger'|'permission'}[],
    trigger?: { clause, events: ['trigger:attack','trigger:attack/self', ...], subject, zone? },
    cost?: { raw, parts }, effect?, modes?,
    targets?: { verb, phrase, filter }[],   // filter = quantity|type|qualifiers|location|value-filter
    patterns: string[]                      // ids from the catalogue in section 5
  }>
}
```

Totals: 1103 cards. **1051 need a script**, 34 are keywords only (no script beyond keyword registration), 2 are reminder pseudo-cards
(Buff `unl-t04`, XP Tracker `unl-t08`), and 16 have no text (6 basic runes, vanilla units, Recruit and Reflection token bodies).
There are 1771 abilities: 495 triggered, 443 keyword lines, 284 spell-effect lines, 177 static, 121 play-modifier, 118 keyword-with-cost,
114 activated, 15 replacement (spells that create replacement or prevention shields count as spell-effect).

How the classifier works, in order: (1) the line is a keyword list, or a cost keyword with its cost; (2) strip the `[Kw][>]` prefixes;
(3) `COST: EFFECT` with every comma-separated cost part recognised means an activated ability; (4) `[Deathknell][>]` or a trigger
opener (`When…`, `At the start/end of…`, `The first/second/third time…`, `Once each turn, when…`, `For each player, the first time…`,
`As I'm revealed…`) means a triggered ability (on spells, a delayed trigger unless it says it works from the trash); (5) `would … instead`
means a replacement; (6) a play modifier (additional, alternative or X cost, play location, self cost change, enters ready/exhausted,
"as you play"); (7) on spells, the resolution text; (8) otherwise a static ability. Effect, target, condition, duration, choice and
scaling patterns are then matched inside each ability's effect text, with quoted granted abilities excluded.

## 3. Prioritised DSL primitives

The counts are numbers of cards. A primitive higher in the list unlocks more cards, so build them in this order.

### Tier 1: needed by more than 100 cards each, or by nearly every batch

1. **Card-script skeleton with ability kinds**: `spell`, `triggered`, `activated` (incl. `mana` abilities that skip the chain, 21),
   `static` (continuous, layer-based), `replacement`, `playModifier`. Gating: `requires: Dependency[]` for Legion (10) / Level N (14) /
   Empowered (28 + 11 conditional "if I'm Empowered") / Mighty (7), and AND-chains for `[>>]`.
2. **Keyword registration with values**, driven by `intrinsicKeywords`: Action 91, Reaction 75, Hidden 45, Equip 43, Empower 40,
   Accelerate 31, Deflect N 29, Shield N 25, Tank 23, Assault N 22, Repeat 20, Ganking 18, Ambush 15, Flow 15, Deploy 14, Hunt N 12,
   Weaponmaster 11, Disarm N 8, Vision 8, Show Off 6, Temporary 6 (plus grants), Quick-Draw 5, Backline 4, Unique 3.
   Keywords can also be **granted** (36 effects, 28 anthem statics), so they must be computed through layers, not read from the CardDef.
3. **Trigger events with subject filters** (`self` / `you` / `opponent` / `any`, plus `@here` for the source's battlefield):
   `play-self` 164, `conquer` 49, `die` 43 + `deathknell` 27, `hold` 43, `play-card` 41 (filters: spell, unit, gear, token, cost ≥ N,
   Power ≥ [A][A], from face down, on an opponent's turn, during a showdown), `attack` 40, `move` 37 (to / from battlefield, the Nth time
   each turn), `defend` 18, phase triggers 17 (start of Beginning, first Beginning, start of Main, end of turn), `become-exhausted` 7,
   `win-combat` 7, `empower` 6. The full list with variants is in section 5.
   Trigger options needed: **intervening "if"** (48), **once per turn / first time each turn / Nth time** (25), "one or more"
   batching (die, stun, discard), and **functions from the trash** (6: ogn-252, rad-010, ogn-037, rad-120, ogn-006, ven-094).
4. **Effects**: `draw` 148, `giveMight(+N, until)` 96 / `-N` 25 with the `minimum 1` floor (9), `playToken(kind, n, {ready, exhausted, at})` 94,
   `dealDamage(N | fn)` 65 + variable amounts 31, `ready` 65, `move` 60 (+ destination base 46, `recall` 13 which is not a move, `swapLocations` 4),
   `kill` 58, `playCardFromZone` 47 with `ignoreCost` 33 / `reduceCost` 6 / destination, `recycle` 41, `buff` 39 / `spendBuff` 9,
   `grantKeyword(kw, value, until)` 36, `returnToHand` 36, `banish` 33, `channel(n, exhausted)` 31, `addResource` 29, `discard` 28, `stun` 26.
5. **Target specs** (129 distinct normalised filters, most common first): any unit 93, friendly unit 77, enemy unit 38, unit at a battlefield 33,

   tags / domains (Mech, Dragon, Bird/Cat/Dog/Poro, Decree domains, named tag), and quantity (one, up to N, any number, all/each, two
